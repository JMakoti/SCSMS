# SCSMS Tauri Backend

This folder contains the Rust backend for the SCSMS desktop app. The frontend is the Next.js app in `apps/desktop`; Tauri hosts that UI and provides native access to the local SQLite database.

## What It Does

- Starts the desktop shell through Tauri 2.
- Creates and owns a local SQLite connection pool.
- Runs the initial SQLite schema migration.
- Exposes a custom `run_sql` command used by Drizzle ORM in `sqlite-proxy` mode.

## Important Files

```text
src-tauri/
  tauri.conf.json          Tauri app, build, window, and bundle config
  Cargo.toml               Rust crate and backend dependencies
  build.rs                 Tauri build hook
  capabilities/default.json
                           Tauri command permission set
  src/
    main.rs                Native binary entry point
    lib.rs                 Tauri builder, startup, command registration
    database/
      connection.rs        SQLite pool creation
      migrations.rs        Initial schema migration runner
      proxy.rs             Drizzle sqlite-proxy command implementation
      seed.rs              Idempotent initial data seeding
      mod.rs               Database module exports
```

## Startup Flow

`src/lib.rs` performs the backend startup work:

1. Builds the Tauri app.
2. Enables logging in debug builds.
3. Creates a SQLite pool for `sqlite:scsms.db`.
4. Runs local schema migrations.
5. Seeds the initial administrator and required sub-county record. It does not seed ward records.
6. Stores the pool in Tauri managed state.
7. Registers commands used by the frontend.

The SQLite database file is created in the Tauri app working directory as `scsms.db`. Seeding is idempotent and does not replace existing records.

## Drizzle SQLite Proxy Flow

The desktop frontend uses Drizzle ORM with `sqlite-proxy` in `apps/desktop/lib/database.ts`.

Instead of opening SQLite directly in JavaScript, Drizzle sends every query to Tauri:

```text
React / Next.js UI
  -> Drizzle sqlite-proxy
  -> invoke("run_sql", { sql, params, method })
  -> Rust Tauri command
  -> sqlx SQLite query
  -> JSON rows returned to Drizzle/UI
```

The Rust command lives in `src/database/proxy.rs`. It accepts:

- `sql`: SQL generated by Drizzle.
- `params`: bound query parameters.
- `method`: Drizzle operation type such as `run`, `all`, `values`, or `get`.

The command binds supported JSON parameter types, executes the query with `sqlx`, and returns JSON rows in the format expected by Drizzle.

## Migrations

`src/database/migrations.rs` loads the generated SQLite migration SQL from:

```text
../../../database/drizzle/sqlite/
```

The migration runner:

- Creates a local `__scsms_migrations` bookkeeping table.
- Skips if the initial schema version is already recorded.
- Records the initial migration if an existing `users` table is detected.
- Applies the initial schema and later subject-combination, ward-geography, and ward-to-sub-county migrations for existing databases.
- Splits each migration on Drizzle's statement breakpoint marker.

## Initial records

`src/database/seed.rs` creates the required Rabai sub-county, administrator role, and `admin@scsms.go.ke` user when they are missing. Ward records are not seeded; create them manually from the Ward page. The password uses `SCSMS_ADMIN_PASSWORD` when configured or falls back to `Admin@123`. The web app uses its own PostgreSQL database; the PostgreSQL seed command does not populate desktop SQLite.

## Commands

Run these from `apps/desktop/src-tauri`.

```powershell
cargo fmt
cargo check
cargo clippy --all-targets -- -D warnings
```

Run the desktop app from the repository root:

```powershell
pnpm.cmd dev:desktop
```

Or from `apps/desktop`:

```powershell
pnpm.cmd tauri:dev
```

## Notes

- The app does not use `tauri-plugin-sql`; database access goes through the custom `run_sql` command.
- `capabilities/default.json` currently grants only `core:default`.
- The `run_sql` command is intentionally powerful because it is the bridge Drizzle uses to access SQLite. Keep frontend code trusted and avoid exposing arbitrary user-written SQL.
